# 04 设计令牌

> **可信度分级（全文每个值都带标记）**
> - **实测**：`System.Drawing.GetPixel` 逐点取样，取样点与像素数在 §7 可复核。
> - **实测推算**：1px 线走亚像素渲染，截图上跨 2 行、无纯色像素；按「两行值之和 = 前景 + 背景」反推得到近似值，误差 ±8/通道。
> - **基准**：来自已完成的 01/02 文档实测结论，本次不再重测，直接采用。
> - **目测估计**：由 JSON 描述 + 视觉比例判断，未做像素级验证。
> - **需补充**：原型未呈现或无法从静帧推断，禁止臆造。

## 5. 设计语言判定

### 5.1 结论

> **是 Material Design 3 风格，但不是纯 M3。**
> 骨架与控件层是 M3 baseline（`#6750A4` 主色 + M3 紫调 surface 色阶 + outlined 浮动标签 + 12/16px 中等圆角 outlined 卡片 + M3 长条 Switch + 全圆角胶囊徽章 + 导航整行填充），
> 但混入了四类非 M3 元素：**Material 2 的静态状态调色板**（`#2E7D32`/`#F57C00`/`#1976D2`/`#BA1A1A`）、**橙色 hover 交互层**（M3 应用 primary/onSurface 的 8%–12% state layer）、**紫蓝渐变登录页 + 品牌装饰条**、以及**灰底表头 `#FAFAFA`**（M3 不用表头底色区分层次，而用 surface 阶）。

### 5.2 逐条证据

| # | M3 特征 | 本设计是否符合 | 证据 |
|---|---|---|---|
| 1 | Baseline primary = `#6750A4`（M3 默认紫 seed） | ✅ 完全一致 | 实测 `#6750A4`，`11-工具` 顶栏 44078 px、`模型监控` 6123 px |
| 2 | M3 surface 家族（紫调近白 `#FEF7FF` / `#FFFBFF` / `#F3EDF7`） | ✅ 一致 | 实测侧栏 `#FEF7FF`、页面 `#FFFBFF`；浅底卡 `#F3EDF7`（目测） |
| 3 | Outlined text field + notched 浮动标签 | ✅ 一致（部分页退化） | `06-Agent-创建`、`02-配置模板`、`07-提示词编辑器`、`11-配置模板-工具模板` 为真浮动标签；`05-知识库-创建`、`11-工具-创建` label 落在框内（退化写法） |
| 4 | corner-medium 12px / corner-large 16px | ✅ 基本一致 | 内容卡 12px、弹窗与插件卡 16px（目测，且 20/24px 混用属偏差） |
| 5 | Outlined card（描边替代 elevation） | ✅ 一致 | 卡片 1px 描边、无投影（实测无灰度渐变） |
| 6 | M3 Switch（长条轨道 + 圆形滑块） | ✅ 一致 | `06-Agent-创建`、`/llmops/cost/security/settings`、`/providers` |
| 7 | 徽章/胶囊全圆角 | ✅ 一致 | 状态胶囊、分类 chip、模型 chip 全 `radius-full` |
| 8 | 导航激活指示器 = 28px 圆角 pill + secondaryContainer | ❌ **偏离** | 实测为**整行直角实底 `#6750A4` + 白字白图标** |
| 9 | State layer（hover 8% primary / onSurface） | ❌ **偏离** | 录屏为**橙色描边/橙色底/整行橙底**（`sec_004/007/041/048/053/069`），非 M3 state layer |
| 10 | 状态色来自 M3 tonal palette（如 error `#B3261E`） | ❌ **偏离** | 实测红 `#BA1A1A` = Material Red 800、绿 `#2E7D32` = Green 800、橙 `#F57C00` = Orange 700、蓝 `#1976D2` = Blue 700，全是 **M2 调色板静态档位** |

**一句话：** M3 baseline 的「壳」+ M2 的「状态色」+ 原型自造的「橙 hover」，落地时按 §2/§3 的覆盖项处理即可，不需要推翻设计语言。

## 6. 组件库选型影响

| 组件库 | 吻合度 | 理由 |
|---|---|---|
| **Vuetify 3（≥3.7，M3 主题）** | **5/5** | ① 原生 M3：`theme` 直接吃 `primary/surface/outline` 语义 key，`#6750A4` 开箱即对；② `VTextField variant="outlined"` 即 M3 notched 浮动标签；③ `VSwitch inset` 即 M3 长条开关；④ `VDataTable` 列定义/行操作/密度可配，覆盖 20 处表格；⑤ 差异只集中在 **4 处覆写**（激活整行、表头底色、橙色 hover、徽章形态），成本可控。风险：`VDataTable` 定制列渲染（两行主副文/进度条）需 `#item` 插槽全手写；包体较大。 |
| **Naive UI** | **3.5/5** | ① 主题变量（`themeOverrides`）表达力最强，橙色 hover、整行激活、表头底色都能纯变量搞定；② 全 TS + 组件按需引入，包体友好；③ 但**没有任何 M3 语义层**：surface 色阶、状态色、outlined 浮动标签（`NInput` 的 label 需自拼 notched 效果）全部手写，M3「原生感」要自己造；④ `NDataTable` 强，但列渲染同样手写。 |
| **Element Plus** | **3/5** | ① `ElTable` 生态最成熟、后台表格开箱即用（含筛选/排序/分页），7 个列表页落地最快；② `ElInput` 默认是**框内 label**（与实测退化页一致，但与本设计目标不符），要做 M3 notched 浮动标签需 hack；③ 主题色可用 CSS 变量改，但配色体系是 Element 自己的蓝灰，M3 surface 阶需整体重写；④ 圆角/描边/阴影语言偏「企业扁」，与 12/16px 描边卡差距中等；⑤ 图标是自有 `ElIcon` 体系，接 Material Symbols 需额外包装。 |
| **Arco Design** | **2.5/5** | ① 设计语言是「企业扁平 + 细描边」，圆角偏小、密度偏紧，与 M3 的中等圆角/宽松间距差距最大；② 无 M3 语义；③ 表格/表单能力达标但定制自由度不如 Naive；④ 生态与中文文档尚可，但需要覆写的面最多（按钮、输入框、开关、表格、徽章几乎全部重写样式）。 |

**推荐：** 用 **Vuetify 3（M3 主题）+ 自建 `StatusBadge`/`AppDataTable`/`WorkflowCanvas` 三个包装层**——M3 骨架零成本拿到，代价只是 4 处样式覆写；若团队已有 Element Plus 存量，则退回 Element Plus + 强制 M3 token 覆盖（接受浮动标签与表头样式需 hack 的额外 3–5 人日）。
