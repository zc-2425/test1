## 三、赵称：需求还原与验收

逐字开场：

> 我们手上只有 62 张截图，没有需求文档。我的活是把它变成能分工、能验收的清单。

**1. 62 张怎么变成 32 条的**

不是简单合并。先按"同一个页面的不同状态算一张"去重——列表的空态、加载态、选中态都并进列表页；然后按家族分：列表 7 个、详情 7 个、创建 5 个、编辑器 3 个、配置类 8 个、其余是看板类。最大的压缩在模板配置：原型里 8 张几乎一样的模板配置页（应用、工作流、Agent、知识库各两版），我改成一条参数化路由 `/explore/:key`，用一份 schema 表驱动，8 张变 1 条。另外有 2 个"页面"我判定成弹窗——LLMOps 的告警中心和设置——它们用 `?alerts=1`、`?settings=1` 挂在路由上，不占独立路由。

最后是 31 条业务路由 + 1 条组件预览页（`/dev/ui`，给我们自己看组件用的）。

**2. 尺寸是量出来的，一开始量错了**

截图是 0.81 倍缩放的，我第一版按图上的像素做，侧栏做成 260、顶栏 76，整站看起来偏胖。后来拿几张图对比同一元素的实际比例，反推出真实值：侧栏 248、顶栏 72、表头 44、行高 52。改完把 tokens 里的变量一起换，页面不用一个个调。

**3. 原型有 bug，我们列了清单主动改**

举四个能当场对照的：

- 表头整体错位——列标题和内容差一列，看着像串色。
- 导航高亮错页——LLMOps 的五个 tab，高亮的是列表页；工具详情高亮在工具市场那一项。
- 同一个状态两个颜色——"草稿"在列表里是灰的，在详情页是蓝的。这条我统到一张映射表（28 个状态 → 5 档颜色），全站只认这一个来源。
- 文字缺陷——`API 密钥` 被容器裁成 `API 密`；工具创建页六个字段名是英文。
- 还有 9 张工作流画布没有连线且节点重叠，以及"运行次数 156"写死在所有卡片上（我们改成按真实数据算）。

改的地方我在清单里逐条标了"照抄 / 修正 / 补全"，评审时可以分开看，不存在"我们偷偷改了原型"。

时间：0:00–0:40 开场；0:40–2:30 合并方法；2:30–4:30 缺陷清单（挑 3 个讲）；4:30–5:30 尺寸这件事 + 验收清单怎么用；5:30–6:00 过渡。

过渡：

> 路由定下来了，但 31 个页面得长得像一套东西。这个基础是邢文权做的。

## 四、邢文权：设计系统与组件库

逐字开场：

> 我不做业务页面，我做的是让别人搭页面时不用重复造轮子的那一层。

**1. 设计令牌：改一处，全站生效**

`tokens.css` 里是一组 CSS 变量：`--layout-sidebar-width: 248px`、`--layout-topbar-height: 72px`、`--color-primary: #6750A4`、`--color-divider: #DBD8DC`，加上 5 档状态色。所有页面只写变量名，不写字面色值。好处很具体：赵称报"侧栏偏胖"的时候，我改一个变量，二十多个页面一起变，不用一页页找。

有个例外要说明：原型里 hover 是橙色（`#F57C00`），但不是每页都有。我把它统一成 `--color-accent`，全站可开关——要么都有，要么都没有，不留一半一半。

**2. 表格组件：列定义驱动**

`AppDataTable` 传一个 columns 数组进去，排序、对齐、闪烁、空态、骨架、行操作全自动。所以后加一个列表页，我只写 4~6 行列定义，不重写表格。27 个组件里这个用得最多。

写这条的时候踩了三个 TypeScript 的坑，都是真事：

- 所有接口返回的数据类型，我从 `interface` 全改成了 `type`。原因是 `interface` 没有隐式索引签名，`AgentDto[]` 不能直接赋给表格的 `Record<string, unknown>[]`，`vue-tsc` 直接报错。改 `type` 就过了。
- 下拉组件我一开始用了 Vuetify 的 `#selection` 插槽，里面写 `item.raw as {...}`，类型推断炸了。最后删掉插槽，改成传一个 `emptyLabel` 属性。
- 模板里我图方便写了 `{{${key}}}` 拼变量，触发 `vue/no-parsing-error: Unexpected end of expression`。最后挪到 script 里写了个 `braced(key)` 函数。

**3. `/dev/ui` 组件预览页**

所有组件的所有状态放一页：正常、空、加载、错误、禁用、hover。改令牌立刻能看到影响，评审也不用满项目翻组件。上台演示我只演示这一页，因为它最不容易翻车。

时间：0:00–0:40 开场；0:40–2:20 令牌；2:20–4:20 表格抽象 + 三个 TS 坑；4:20–5:30 演示 `/dev/ui`；5:30–6:00 过渡。

过渡：

> 组件有了，剩下是拼成 31 个页面，还有全项目最麻烦的那块画布。南海鑫。

## 五、南海鑫：业务页面与画布

逐字开场：

> 我把组件和后端接口接成用户能点的东西。页面数量看着多，真正花时间的是画布。

**1. 页面：验收标准是"断网会怎样"**

31 个业务页全部接真接口。列表有搜索、筛选、排序、分页、空态；详情有加载骨架、不存在的提示；创建页有必填校验和失败回滚。我验收不看截图像不像，而是把后端停掉刷新——如果白屏就是没做错误态。

**2. 画布：四个交互全是手写的**

没引 `@vue-flow/core`，因为它自带一套节点模型和样式，跟我们的 M3 对齐比我手写还费劲。手写要解决四件事：

- 平移：空白处 pointerdown，改 offset。
- 缩放：滚轮改 scale，要 0.4~1.6，而且要**以光标为锚点**，不然缩放时图会往一边飞。
- 拖节点：位移要除以 scale 才是画布坐标——这行一开始漏了，缩放后拖拽就跟手。
- 连线：从节点右侧圆点拽出临时线，松手落在另一个节点上才建边，落在空白处不建。

**3. 三个真实的坑**

- Vite 隔三差五崩，报 `EBUSY: resource busy or locked, watch '...\.ComponentPlayground.vue.<pid>.<uuid>.tmpdir\...'`。原因是编辑器保存时先写临时目录再移动，Vite 监听到一半文件没了。在 `server.watch.ignored` 里加了三条 glob 才稳住。
- 连线一开始是直线，跨节点时线从节点上穿过去，很乱。改成从节点底部到下一个节点顶部的竖向曲线，同时强制单列布局。
- 下拉框没选的时候提交的是空字符串。根因是我写的 `textValue()` 只在"不是字符串"时回落，空字符串本身就是 string，所以原样提交了，工具的类型字段存成空、列表里显示成 `-`。后来改成 trim 后为空也回落，并给 11 个下拉补了默认值。

时间：0:00–0:40 开场；0:40–2:00 页面验收标准；2:00–4:20 画布四个交互（边讲边拖）；4:20–5:30 三个坑；5:30–6:00 过渡。

演示动作：拖一个节点 → 滚轮缩放 → 从圆点拉一条线 → 点节点改个名 → 保存 → 按 F5，节点和连线还在。

过渡：

> 前端所有请求最后都打到一个后端上，80 个接口、23 张表。侯子健。

## 六、侯子健：接口与数据模型

逐字开场：

> 我负责让前端不用猜、后端不用返工的那层：接口形状、表结构、还有谁能进得来。

**1. 80 个接口，大部分是一个工厂产出的**

9 个资源共用一套通用 CRUD：分页、搜索、筛选、排序、404 全都统一，所以 `GET /api/tools` 和 `GET /api/agents` 的行为一模一样，前端列表逻辑只写一次。真正写专用端点的只有 8 个：跑工作流、重建索引、检索、跑评测、厂商连通性测试、会话详情、trace 列表、批量上传。新增一个资源只要声明字段，不用复制整个路由文件。

**2. 数据层两个坑**

- SQLAlchemy 2.1 不接受没有时区的时间，seed 一跑就报 `Datetime values must have timezone information`。所有时间字段改成带 UTC 时区，`_now()` 一起改。
- 测试把临时库写进了仓库：跑完 pytest 项目里多出 `server/ai-agent-platform-test-*/` 目录。改成固定写到 `server/.pytest_tmp/`，并加进 `server/.gitignore`。

**3. 32 条测试，挑三条讲**

- `?order=sideways` 应该返回 422，不是静默忽略——这条是防止参数写错还能跑。
- `?sort=not_a_field` 应该回落到 id 排序返回 200，不能 500——排序字段是前端传的，随时可能传错。
- 空图运行工作流应该 400 并说明"先保存节点"，不是 500。

还有一条容易被忽略：测试环境必须隔离。我们 `.env` 里有真的 API Key，第一版测试跑起来会真发请求、真扣钱。所以 conftest 里把四个 Key 环境变量全部清空，模式强制 mock。

时间：0:00–0:40 开场；0:40–2:20 通用 CRUD；2:20–4:10 两个坑 + 32 条测试；4:10–5:30 隔离这件事；5:30–6:00 过渡。

过渡：

> 接口能跑了，但"真的会思考"是他接进来的。寇梦涛。

## 七、寇梦涛：模型接入与 RAG

逐字开场：

> 我负责让模型真被调用、文档真被检索、回答能追溯。

**1. 一个客户端打通四家厂商**

DeepSeek、OpenAI、Ollama、硅基流动都是 OpenAI 兼容协议，所以我只写了一个 httpx 客户端，没引 openai SDK。流式用 SSE，四类事件：delta 增量、result 收尾、error 错误、DONE 结束。前端解析有个坑：网络会把一个事件切成两半，所以不能逐块 parse，要留 buffer、按空行切。

没配 Key 的时候不假装成功：后端回落本地模拟，结果事件里带 `mode: "mock"`，界面上直接显示"模拟输出"。界面上那行小字会写清楚当前是 `真实调用 · siliconflow / DeepSeek-V4-Flash` 还是模拟。

**2. RAG 三个决定，都有实测**

- 向量存 float32 BLOB，不存 JSON。实测 1 万个分块 1024 维：BLOB 39.1MB，JSON 文本 198MB——每条 JSON 20KB，膨胀 5 倍。
- 检索用 numpy。纯 Python 算 1 万条余弦是 615ms/次，numpy 是 2.1ms。加上读库 30ms，整体 32ms，比调一次 embedding 接口（约 190ms）还快。
- 没 Key 时用的"假向量"不是随机数。我用字符 bigram 做特征哈希，词面相近的文本向量也相近，所以离线状态下检索排序仍然有意义，测试也能断言排序对不对。

整条链路：上传 → 解析 → 按段落切块（800 字符、150 重叠）→ bge-m3 出 1024 维 → 存库 → 查询时取 top-k → 命中片段按编号拼进系统提示词 → 回答带 `[1][2]` → 引用跟消息一起存库。

**3. 两个故障**

- 硅基流动报 `400 code 20012`。原因：提示词配置里存的模型名是 `gpt-4o`（裸名），而硅基流动的模型 id 必须带厂商前缀，比如 `deepseek-ai/DeepSeek-V4-Flash`。加了回落规则：id 里没有 `/` 就用该厂商默认模型。顺带发现 V3.2 回答一次要 17~23 秒，换 V4-Flash 后 1.6~3.2 秒。
- 评测第一版没传知识库，4 条用例全跑裸模型，单次 97.8 秒、只有 71 分。加上知识库参数和 400 token 上限后，11 秒、100 分。

**4. 评测怎么判分**

不用模型给自己打分——同一份回答两次能给不同分。用"期望要点命中率"：每条用例配几条必须先出现的内容，命中几条算几分，纯字面匹配。对照实验：挂知识库 4/4 通过、100 分；不挂 2/4、71 分，缺的正好是 `1-2 个工作日`、`3-7 个工作日`、`普通会员`、`银卡` 这些文档里的具体词。

时间：0:00–0:40 开场；0:40–2:10 客户端与降级；2:10–4:20 RAG 三个决定；4:20–5:20 两个故障；5:20–6:00 评测 + 过渡。

演示：知识库详情页搜"怎么开发票"→ 看命中文档和分数；切到提示词页选知识库 → 运行 → 回答里出现 `[1]`。

过渡：

> 检索和生成都有了，但一次调用只是起点。怎么把它跑成一条流程、每一步都留痕，是韩子斌。

## 八、韩子斌：工作流引擎与埋点

逐字开场：

> 我负责把画布上的图变成真的执行，并让每次运行都能查。

**1. 之前是假的，现在是真的**

之前点运行，后端按节点数编步骤——步数对得上，内容是写死的字符串。现在节点和连线存在两张表里，引擎从开始节点沿连线逐个执行：LLM 节点真调模型、检索节点真查知识库、问答节点用 `{{变量}}` 模板带上检索结果再问一次、条件节点求值后选分支。

有三种节点我们没有执行体：Agent、代码执行、HTTP。运行时明确标"跳过"并写原因，不假装跑过。

**2. 两个 bug**

- 启动顺序错了：我先把"给老工作流补图"放在灌种子之前，新库一个工作流都没有，永远补不到图，测试里 `assert 0 >= 2` 直接红。改成先灌种子再补图。
- 结束节点取错了变量：它优先读 `answer`，结果上游那个 LLM 的输出被丢掉，最终答案停在问答节点。改成输出"流进来的值"（`last_output`）。

**3. 埋点：LLMOps 的数字终于是真的**

引擎每跑一个 LLM 节点写一条 trace；一次运行写一条会话（用户输入 + 最终回答两条消息，带引用）。LLMOps 的调用量、成功率、延迟、成本全从 trace 聚出来。

清理的时候有个判断依据：删掉 932 条种子 trace，识别标准是"没有 conversation_id"——真实调用一定有会话归属。删完概览是 0，跑一次对话变成 1、成功率 100%、849ms、$0.00002。

时间：0:00–0:40 开场；0:40–2:30 真假对比 + 跳过节点；2:30–4:00 两个 bug；4:00–5:40 演示（跑 8 节点 → 看 trace → 看 LLMOps）+ 收尾；5:40–6:00 谢谢。

演示：打开 wf-001 点运行，展示 8 步输出（开始 / LLM / 检索 / 问答 / 条件 / 转换 / LLM / 结束）；切到 LLMOps 概览看调用量 +1。

## 九、协作过程

**接口怎么定的**：先定 DTO 再写页面。前端只用后端声明的字段，后端 id 用可读字符串（`wf-001`、`conv-xxx`），不用适配数字。DTO 一律用 `type` 不用 `interface`，原因在邢文权那节讲过。

**联调顺序**：列表 → 详情 → 创建。因为列表最简单、能最快暴露接口问题（分页参数、排序字段、空数据），列表通了后面都顺。

**互检怎么做的**：

| 谁产出 | 谁检查 | 检查什么 |
|---|---|---|
| 侯子健接口 | 南海鑫 | 33 个视图全接真接口，任何 4xx/5xx 回抛 |
| 寇梦涛的检索与引用 | 韩子斌 | 引用有没有随消息落库、trace 的 token 和耗时是不是真的 |
| 邢文权组件 | 南海鑫 | 组件在真实业务页里有没有走样 |
| 赵称验收清单 | 全员 | 逐条对照原型，标照抄/修正/补全 |

**统一口径**：全场只认第一节那张数字表。演示只三个人碰鼠标，其余人讲。现场断网或后端挂了，就切"模拟输出"模式讲链路——我们有显式降级，这本身就是可讲的点。
