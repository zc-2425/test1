## 二、项目概述与汇报主线（开场 60 秒，赵称讲）

### 【逐字】开场

> "各位老师、同学好，我们组做的是『AI 智能体应用开发平台』。
> 一句话解释它：**它本身不是聊天机器人，而是生产聊天机器人的工厂**。业务同学不用写代码，通过模板、配置和拖拽画布，就能做出一个能上线、能计费、能追溯的 AI 应用。
> 我们的起点是 62 张原型图，终点是 32 条真实可点的路由、80 个后端接口、23 张表，以及三条真正跑通的链路——真模型调用、真知识检索、真流程执行。
> 下面 6 个人，每人 6 分钟，按『原型还原 → 界面基建 → 业务页面 → 后端数据 → 模型与知识 → 执行与可观测』的顺序讲。"

### 【要点】平台解决的三件事

| 诉求 | 没有平台会怎样 | 平台给什么 |
|---|---|---|
| **可治理** | 各团队自己申请 Key，成本不可见，出问题查不到 | 统一模型接入、预算告警、每次调用留 trace |
| **可复用** | 每个需求从零写，知识不进系统 | 模板、工具、知识库、工作流可被复用 |
| **可运营** | 上线后不知道好不好 | 会话全留痕，指标来自真实调用而非编造 |

### 【要点】汇报主线（全员必须讲在这条线上）

```
62 张原型画布
   ↓ 还原 + 修正原型自身的 bug
32 条真实路由（33 个视图）
   ↓ 背后是一套真系统
80 个接口操作 / 23 张表
   ↓ 三条真链路
真模型调用  →  真知识检索（带引用）  →  真流程执行
   ↓ 可度量
LLMOps 指标来自真实 trace；评测集能打出分数
```

> 这句话可以反复用来收尾：**"我们不是把界面画出来了，而是把界面背后的东西做真了。"**

### 4.3 南海鑫 — 业务页面与画布交互

**【逐字】开场**

> "我把设计系统和后端接口接成用户能点的东西。工作量最大的不是页面数量，而是画布——全项目只有它没有现成组件能套。"

**【要点 1】31 个业务页面全部接了真接口**

> "验收标准不是『截图像不像』，而是『断网能不能看到合理错误』。所以每个列表页都有搜索、筛选、排序、分页和空态；每个详情页都有加载骨架和不存在时的提示；创建页有字段校验和失败回滚。这些都是接了真接口才敢这么测的。"

**证据**：随便打开一个列表页做搜索/翻页；把后端停掉再刷新，会看到错误提示而不是白屏。

**【要点 2】自研工作流画布：四个交互都是手写的**

> "没有引 `@vue-flow/core`，因为它自带一套节点模型和样式系统，和我们的 M3 视觉对齐成本比手写更高。手写要解决四件事：**平移**——空白处按下拖动改偏移；**缩放**——滚轮改比例，而且必须以光标为锚点，否则会往外飞；**拖节点**——位移要除以缩放比例才是画布坐标；**连线**——从节点右侧圆点拖出临时线，松手落在另一个节点上才建边。"

> "这一点是最近才真正成立的：之前节点只存在前端内存里，刷新就没了。现在保存会把节点和连线写到数据库，刷新后原样回来。"

### 4.4 侯子健 — 接口、数据模型与鉴权

**【逐字】开场**

> "我负责『前端不用猜、后端不返工』的那层：接口形状、数据模型，以及谁能进得来。"

**【要点 1】80 个接口操作，大部分靠一个工厂收敛**

> "9 个资源共用一套通用 CRUD：分页、搜索、筛选、排序、404 全部统一，所以 `GET /api/tools` 和 `GET /api/agents` 的行为完全一致，前端的列表逻辑只写一次。只有真正特殊的行为才写专用端点：运行工作流、重建索引、检索、跑评测、厂商连通性测试。收益是——新增一个资源只要声明字段，不用复制一整个路由文件。"

**证据**：`/docs` 的 OpenAPI 页面可现场数出 47 个路径、80 个操作。

**【要点 2】23 张表，向量为什么单独一张**

> "文档文本在 `document_chunks`，向量在 `chunk_embeddings`，刻意分表：向量是 1024 维 float32，一条 4KB；如果和文本放同一行，列表页查文档名时会把这些大字段一起搬出来。存储上有个实测：1 万个分块用 float32 BLOB 是 39MB，如果存成 JSON 文本会膨胀到 198MB。改字段时不删库——启动时做 `ALTER TABLE ADD COLUMN` 补列，练手阶段不上 Alembic，但这笔债我写在文档里了。"

**证据**：指着表结构问任意一张表的字段与索引理由。

**【要点 3】鉴权、守卫与 32 条测试**

> "登录返回 token 并持久化，前端守卫拦截未登录访问并带上 `?redirect=` 原路返回，登录后跳回原页面。测试有 32 条，覆盖分页、搜索、404、创建-修改-删除、流式事件、引用落库、评测判分、图读写、空图返回 400。而且测试环境会**强制 mock 模式并把 API Key 置空**——否则本机配了 Key，跑测试会真的扣钱。"

### 4.5 寇梦涛 — LLM 接入与 RAG

**【逐字】开场**

> "我负责让这个平台真的会思考：模型真被调用、知识真被检索、答案能溯源。"

**【要点 1】一个客户端打通所有厂商，且缺 Key 时诚实降级**

> "DeepSeek、OpenAI、Ollama、硅基流动都遵循 OpenAI 兼容协议，所以我只写了一个 httpx 客户端，没有引 openai SDK。流式用 SSE 四类事件：delta 增量、result 收尾、error 错误、DONE 结束；前端按空行切事件，并且处理『一个事件被网络切成两半』的情况。最关键的一点：**没配 Key 时不会假装成功**——后端回落本地模拟，并在事件里回报 `mode=mock`，界面上直接显示『模拟输出』角标。"

**证据**：界面上「测试运行」卡片副标题会写明当前是 `真实调用 · siliconflow / DeepSeek-V4-Flash` 还是「模拟输出」。

**【要点 2】RAG 七步，每一步都能指出来**

> "上传 → 解析 → 按段落切块（800 字符、150 重叠）→ bge-m3 生成 1024 维向量 → 存 SQLite 的 float32 BLOB → 查询时用 numpy 算余弦取前 k → 命中片段按编号拼进系统提示词 → 回答里带 `[1][2]`，而且**引用会随消息一起存库**。
> 为什么用 numpy：纯 Python 算 1 万块要 615 毫秒，numpy 只要 2 毫秒；加上读取 30 毫秒，整体 32 毫秒——比调一次 embedding 接口还快。"

**演示动作（40 秒）**：知识库详情页输入"怎么开发票" → 点检索 → 展示命中文档、分数、片段；再切到提示词页绑定知识库 → 运行 → 回答里带 `[1]`。

**【要点 3】评测：不用模型打分，用要点命中率**

> "让模型给自己打分不稳定，同一份回答两次能给不同分。所以我们的判分是**期望要点命中率**：每条用例配几条必须先出现的内容，命中几条算几分。纯字面匹配，可复现、可离线、零成本。
> 对照实验很能说明问题：同一个提示词，**挂知识库 4/4 通过、100 分；不挂知识库 2/4、71 分**，缺的正好是文档里的具体数字——`1-2 个工作日`、`3-7 个工作日`、`普通会员`、`银卡`。这就是 RAG 的价值被量化出来的样子。"

**证据**：评测页两次运行并排，100% 与 71% 可现场对比。

### 4.6 韩子斌 — 工作流执行引擎与可观测

**【逐字】开场**

> "我负责把画布上的图变成真的执行，并让每一次运行都能被追溯。"

**【要点 1】从"编步骤"到"真执行"**

> "之前点运行，后端是按节点数编出来的假步骤——步数是对的，内容是写的死字符串。现在节点和连线真的存在数据库里，引擎从开始节点沿连线逐个执行：LLM 节点真调模型、检索节点真去知识库查、问答节点用 `{{变量}}` 模板加上下文再问一次、条件节点求值后选分支。
> 这里有个我们坚持的设计：**Agent、代码执行、HTTP 这三种节点没有执行体**，运行时会明确标『跳过』并写明原因，绝不假装跑过。诚实地少一步，比假装全跑完更有价值。"

**【要点 2】可控性：防环、隔离、不做任意求值**

> "三条约束：节点只执行一次（用已访问集合），加步数上限 50，防止连线成环导致死循环；单个节点报错不影响整条流程，会记在那一层；条件表达式只支持 `contains:`、`equals:` 这类白名单写法，**不做任意表达式 eval**——因为那等于把服务器的执行权交给用户填的字符串。"

**【要点 3】全链路可观测：指标不是编的**

> "每次运行会写一条会话（用户输入 + 最终回答两条消息，带引用）和逐节点的 trace。LLMOps 里的调用量、成功率、平均延迟、成本，全部从 trace 表聚合出来——你跑一次对话，曲线就变；不跑，它就是 0。这一点是最近才成立的，之前那些漂亮曲线读的是随机种子数据，现在是真的。"

**演示动作（40 秒）**：打开工作流 wf-001 → 点运行 → 展示 8 步的真实输出（开始 / LLM / 检索 / 问答 / 条件 / 转换 / LLM / 结束）→ 切到 LLMOps 概览看调用量 +1。

**时间分配（360 秒）**

| 时间 | 内容 |
|---|---|
| 0:00–0:40 | 角色定位 |
| 0:40–2:40 | 要点 1：真假对比 + 跳过节点的设计 |
| 2:40–4:10 | 要点 2：三条约束 |
| 4:10–5:40 | 要点 3：跑一次 + trace + LLMOps |
| 5:40–6:00 | 收尾，回扣主线 |

**【逐字】收尾**

> "回到最开始那句话：我们不是把界面画出来了，是把界面背后的东西做真了。谢谢大家。"

## 五、团队协作过程说明

### 5.1 怎么衔接：一份契约 + 一条主线

- **契约先行**：前端与后端只通过 DTO 契约衔接，接口形状先定、页面后写；后端 id 用可读字符串（`wf-001`、`conv-xxx`），前端不需要适配数字 id。
- **主线固定**：「原型 → 路由 → 接口 → 真链路 → 可度量」。任何人汇报都不能跳出现场这条线，否则听众拼不起来。
- **两套编号刻意分开**：P0–P12 是「把画布做成界面」，R1–R6 是「把界面做成真系统」。这样复盘时不会把"画了页面"和"真能跑"混为一谈。

| 产出 | 质检 | 具体动作 |

| 侯子健的接口 | 南海鑫 | 33 个视图全量接真接口，任何 4xx/5xx 回抛 |

### 5.3 怎么统一口径

- **数字只认附录 A**，7 个核心数字全场唯一版本。
- **演示只让 3 个人碰鼠标**，其余人讲，避免抢鼠标。
- **降级预案**：现场断网或后端挂了，就切"模拟输出"模式讲链路——我们有显式的降级路径，这本身是加分点。

### 5.4 三个真实的踩坑故事（Q&A 时用得上，增强可信度）

| 故事 | 现象 | 根因 | 改了什么 |
|---|---|---|---|
| **按钮点了没反应** | 登录页点"登录"毫无响应 | 无头浏览器里 JS 的 `el.click()` 不触发原生表单提交 | 改用真实鼠标事件验证；并接受了"接口 200 ≠ 用户能用"这条教训 |
| **改了代码像没生效** | 重启后端后行为还是旧的 | 旧进程占着端口，新进程启动失败退出，我们查到的是旧进程 | 重启前先查端口占用并确认释放 |
| **评测跑了 97 秒还只有 71 分** | 评测极慢且分数低 | 评测页没传知识库，裸模型在答通用知识，输出又长又偏 | 页面加知识库选择 + 回答长度上限 400 token，降到 11 秒、100 分 |
